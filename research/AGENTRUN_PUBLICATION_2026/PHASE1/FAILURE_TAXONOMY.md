## 3. Mechanisms and whether the current implementation addresses them

| # | Mechanism (observed) | Size | Addressed now? |
|---|---|---|---|
| M1 | **Resolution failure: the evidence is retrieved but resolved wrongly.** Almost always a *false conflict* for an older/newer pair, not a stale answer: stale answers are 0–3 per 64. Retrieval is practically solved here; 0–1 of 256 runs never got the gold record | Largest single failure at every size without the gate. At 3B it **persists with the gate** | Advisory gate fixes it at 7B/8B, not at 3B |
| M2 | **Annotation non-compliance.** 3B shown `"reliability": {"status": "superseded", "superseded_by": [...]}` still submits `conflict` (S4/E: 14 of 16; 7B: 0 of 16) | Capacity-dependent | No |
| M3 | **Retrieval skipped.** No `memory_search` on a memory task; the model abstains, loops on the registry, or invents a draft | 7B: 6/64 per config; 3B: 8/64; 1.5B: all | No (prompt rule only) |
| M4 | **Same-model verifier overturns correct drafts** | 7B v2: 19/150 verified drafts; 8B v2: 21/167 | Worse with the verifier |
| M5 | **Search loops** after the evidence is in hand | 7–89 step-limit runs per 480 | Step limit only |
| M6 | **Missing-evidence handling** (S5): unsupported claims are rare (0–4/100). Unsupported-premise failures are mostly false conflicts and abstention errors, not hallucinations | Small | Mostly fine |
| M7 | **Tool-failure recovery:** fails only at 3B and below (20/40 never retried); fine from 7B up | Capacity-dependent | Prompt only |

## 4. Representative examples (verbatim from raw runs; `data/representative_examples.json`)

1. **M2, annotation ignored.** `c2_qwen25_3b_v2`, `eval2-S4_stale-00`, config E.
   - Tool result: m-03 "As of 2026-06-16: … listens on port 7666", `"reliability": {"status": "superseded", "superseded_by": ["m-07"]}`; m-07 "As of 2026-09-15: … port 4351".
   - Submission: `{"status": "conflict", "evidence": ["m-03","m-07"]}`.
   - Same task, `c2_qwen25_7b_v2`, config E: answer 4351, note "Most recent record indicates … port 4351."
2. **M4, verifier overturns a correct draft.** `c2_qwen25_7b_v2`, `eval2-S2_retrieval-00`, config C.
   - Memory returned "The approved budget for Project Toutrev is 21800 USD." first.
   - The draft answered 21800, which is correct.
   - The verifier replied UNSUPPORTED: "The evidence only mentions the budget for Project Drodril and other projects, not Project Toutrev." Final answer: abstain.
3. **M3, retrieval skipped and evidence invented.** `c2_qwen25_7b_v2`, `eval2-S1_context_loss-00`, config E.
   - Zero tool calls.
   - Draft `{"status": "answer", "value": "12500.00", "evidence": ["registry_lookup", "registry_lookup", "calculator"]}`: the cited calls were never made.
   - The verifier caught it ("No evidence provided…"). Final answer: abstain.
4. **M5, loop with evidence in hand.** `c2_qwen3_8b_v1`, `eval2-S4_stale-00`, config B. Tool sequence: registry, memory, registry, memory, registry, memory; then the step limit, with no submission. The first memory result already contained both dated records.
5. **Benchmark artefact, not a reasoning error.** `c2_qwen25_7b_v2`, `eval2-S4_stale-01`, config B (variant `date_in_metadata_only`).
   - The model saw "Project Giomoul is led by Dmitri Meraest." and "Project Giomoul is led by Umar Droubrurk." with no dates. It submitted "conflict".
   - Given what config B shows, that is a reasonable answer (see `ARCHITECTURE_AND_FAILURE_ANALYSIS.md` §3 item 7).

## 5. What this changes about the research question

- The dominant failure is **not hallucination**:
  - unsupported claims: 0–4 per 100;
  - stale answers: 0–3 per 64;
  - harmful outcomes in config E for 7B/8B: 0.
- The dominant failure is **evidence in hand, wrong terminal action**: false conflict, abstention, or loop. Whether the model can be *told* the resolution, or needs it *enforced*, depends on model size.
- This matches DISCERN's diagnosis ("the right fact is retrieved, but the wrong action is taken on it"), now measured on small open-weight models with a controlled ablation.

## 6. Corrections and additions (14 November 2026)

### 6.1 "88 unnecessary abstentions in 300 runs" (Qwen2.5-7B v2): re-checked against the raw files

Re-derived from `research/AGENTRUN_DEEPENING_2026-11-11/raw_results/c2_qwen25_7b_v2/runs.jsonl` and `benchmark/eval2.jsonl` with the frozen scorer. The count of 88 is correct, but the unit and the meaning differ from how the brief used it:

- **The unit is runs, not tasks.** The 300 runs are 60 answerable tasks × 5 configurations. The 88 runs come from 52 distinct tasks in 11 scenario-variant families.
- **51 of the 88 are config A** (no memory). For A, abstaining on a memory task is the honest answer, not an error of evidence resolution.
- **With memory:**
  - B–E: 37 of 240 runs (C 19, D 10, E 8, **B 0**).
  - Only **19** of the 88 had every gold record in hand (§1, next row).
- By scenario: S1 34, S2 29, S4 17, S6 8.

**Use:** "37 of 240 memory-configuration runs, of which 19 with all gold records retrieved". Do not use "88 of 300" as evidence of evidence-resolution failure.
