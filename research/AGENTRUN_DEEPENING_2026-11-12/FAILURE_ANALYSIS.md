## Key failure patterns

### 1. Format errors are an artifact of prompt rigidity, not model limitation

The v2 harness eliminates nearly all format errors (66→6 for Q2.5-7B, 28→0 for Q3-8B) by adding a repair turn and explicit formatting rules. The 1.5B model under v1 has 100% format errors (480/480), but under v2 it produces only 8/480. This means the v1 format errors measured model compliance with a specific output format, not model understanding of the task.

### 2. Over-abstention is the dominant non-format failure mode

After format errors are resolved, over-abstention (the model says "I don't know" when the answer is available) accounts for the largest share of failures. Under v2:
- Q2.5-7B: 104/480 (21.7%)
- Q3-8B: 84/480 (17.5%)

Over-abstention is concentrated in scenarios where the model encounters conflicting or stale information and chooses to refuse rather than attempt to resolve the conflict.

### 3. The verification penalty is over-abstention

When the verifier is added (config C), the model checks its own retrieved answer before responding. Without provenance metadata to explain where the answer came from, the model frequently second-guesses correct answers and refuses to commit. This manifests as an increase in over-abstention rather than an increase in wrong answers.

### 4. Qwen3-8B S5 abstention failure (v1 only)

Under v1 harness, Qwen3-8B with the full pipeline (config E) correctly abstains on unsupported questions only 1/16 times. The model appears to use its memory store to fabricate plausible-sounding answers to questions that are genuinely unanswerable.

Root cause: Qwen3-8B is more creative in leveraging retrieved context. When memory provides any related information, it synthesizes an answer rather than admitting the question is beyond its knowledge. The v2 formatting rules explicitly instruct the model to say "unsupported" when no evidence supports the answer, fixing this completely (16/16 correct).

### 5. The 3B model produces the most harmful answers

Qwen2.5-3B has the highest harmful-answer rate: 24/480 (5.0%) on v1 and 37/480 (7.7%) on v2. This is because the 3B model partially follows instructions — enough to produce formatted answers — but lacks the capacity to reliably distinguish correct from incorrect information. The reliability pipeline cannot compensate because the model cannot properly execute the verification and provenance checks.

### 6. Stale-memory scenario (S4) is the hardest

Even with the full pipeline, stale-memory tasks are where the system struggles:
- v1 pooled, config B: 4/32 (12.5%)
- v1 pooled, config E: 25/32 (78.1%)
- v2 pooled, config E: 32/32 (100%)

The reliability gate is essential for stale-memory scenarios. Without it, the model has no mechanism to prefer newer information over older cached values.
