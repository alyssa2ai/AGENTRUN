## Top-line findings

### 1. Memory reliably improves agent task completion

Pooled across both models (v1 harness, 96 fresh tasks):
- **Stateless → Retrieval: +32.3 pp** (24.5% → 56.8%, p < 0.0001)
- **Stateless → Full pipeline: +50.5 pp** (24.5% → 75.0%, p < 0.0001)

With the v2 harness (repair turn + two rules):
- **Stateless → Retrieval: +52.6 pp** (29.2% → 81.8%, p < 0.0001)
- **Stateless → Full pipeline: +63.0 pp** (29.2% → 92.2%, p < 0.0001)

### 2. Verification without provenance sometimes hurts

The verifier consistently degrades performance when provenance metadata is absent:
- v1 pooled: **C − B = −5.2 pp** (p = 0.006)
- v2 pooled: **C − B = −11.5 pp** (p < 0.0001)

This is a real, reproducible finding: verification without source provenance causes the model to second-guess correct answers.

### 3. Reliability gates rescue stale-memory scenarios

Stale-memory tasks (S4) are the hardest scenario. Pooled v1 results:
- Retrieval only: **4/32** (12.5%)
- With provenance: **10/32** (31.3%)
- With reliability gate: **25/32** (78.1%)

### 4. Model capacity determines which components help

**1.5B (Qwen2.5-1.5B):** Non-functional. 0% success on v1 (100% format errors). ~20% on v2 with no component effect.

**3B (Qwen2.5-3B):** Memory helps (+29.2 pp), but verifier/provenance/gate effects are either non-significant or harmful.

**7B (Qwen2.5-7B):** Full gradient of component effects is significant. The intended design space.

**14B (Qwen2.5-14B):** Memory strongly helps (+34–48 pp), but the additional reliability components (verifier, provenance, gate) show no significant marginal benefit — the model already handles these scenarios well enough without them.

### 5. Retrieval degrades at scale without proper retrieval

- Hash-based retrieval with 2,000 background records: recall drops to 0.76, success drops from 71.4% to 41.7% (−29.7 pp, p < 0.0001)
- BM25 retrieval with 2,000 records: recall stays at 1.00, success at 70.3% (no significant drop from no-padding)
- Dense retrieval (bge-small): not run (job 14 never started)

### 6. Harness v2 substantially reduces format errors

The v2 harness (repair turn + two formatting rules) reduces format/step-limit failures from ~22–24% to ~1–4% across both models (p < 0.0001). Qwen3-8B under v2 reaches **95.8% task success** at the full pipeline configuration.
