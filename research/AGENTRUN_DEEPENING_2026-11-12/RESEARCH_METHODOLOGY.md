# Campaign 2 — Research Methodology

## Overview

Campaign 2 evaluates how persistent memory, retrieval quality, evidence provenance and verification affect multi-tool LLM agent reliability across model capacities from 1.5B to 14B parameters.

## Benchmark design

### Evaluation split: eval2 (96 tasks)

- **6 scenarios × 16 tasks** per scenario.
- Frozen in `benchmark/FREEZE_eval2.json` before any Campaign 2 experiment ran.
- Generated by `scripts/build_eval2.py` from a deterministic seed.
- Entity names, expected values and prompts are all novel — no overlap with training data, legacy benchmarks, or the first evaluation split.

### Scenarios

| ID | Name | Tests |
|---|---|---|
| S1 | Context loss | Agent must recover information from memory after context window is cleared |
| S2 | Retrieval | Agent must retrieve the correct record from a populated memory store |
| S3 | Conflict | Memory contains conflicting information; agent must identify and resolve the conflict |
| S4 | Stale memory | Memory contains both outdated and current values; agent must prefer the current one |
| S5 | Unsupported | Question is about an entity not in memory; agent should abstain |
| S6 | Tool failure | A tool the agent would normally use is unavailable; agent must fall back to memory |

### Configurations (memory pipeline components)

| Config | Description |
|---|---|
| A | Stateless baseline — no memory, no retrieval |
| B | Memory with retrieval — agent can query a persistent memory store |
| C | Verified retrieval — agent checks retrieved answers before responding |
| D | + Provenance — retrieved records include source and timestamp metadata |
| E | + Reliability gate — agent applies a reliability assessment before committing to an answer |

Each configuration builds on the previous one. All use the same task prompts.

## Harness variants

| Harness | Features |
|---|---|
| v1 | Frozen control harness. No repair turn. Original formatting expectations. |
| v1r | v1 + one repair turn if the initial output has a format error. (Not completed.) |
| v2 | v1r + two explicit formatting rules in the system prompt. |

## Execution environment

- **Hardware:** 2× NVIDIA L40 (48 GB each), 96 CPUs, ~515 GB RAM.
- **Scheduler:** Slurm, partition `gpu-nodes`, max 2 concurrent jobs.
- **Inference:** HuggingFace Transformers with `HF_HUB_OFFLINE=1` (all models pre-downloaded).
- **Decoding:** Greedy (temperature 0) unless stated otherwise.
- **Serving:** Local vLLM or HF pipeline (model-dependent).

## Scoring

### Ablation runs (eval2 split)

Scored by `memlab.score_run()`:
1. Parse the model's output into a structured answer.
2. Compare against the expected value using string matching (case-insensitive, whitespace-normalized).
3. Classify the outcome (correct, format_error, max_steps, over_abstain, false_conflict, wrong_value, stale_value, unsupported_claim, arbitrary_pick).
4. A task is "successful" if the outcome is "correct".
5. A task is "harmful" if the outcome is any of wrong_value, stale_value, unsupported_claim, or arbitrary_pick.

### Legacy 23-task benchmark

Scored by `eval/harness.py` using the R0 rule (original pass/fail criteria, frozen since the initial AGENTRUN release).

### Benchmark v2 dev split (55 tasks)

Scored by `scorer_v2` using the R2 rule (updated scoring that distinguishes tool-necessary, tool-optional and tool-unnecessary tasks).

## Leakage audit

All 17 audit checks pass (`tables/leakage_audit_eval2.json`):

1. eval file matches frozen hash
2. prompts match frozen reference
3. eval regenerates from seed
4. dev/eval entities disjoint
5. eval2 entities disjoint from first eval split
6. eval2 prompts disjoint from first eval split
7. harness variants match frozen reference
8. dev/eval prompts disjoint
9. eval prompts unique
10. dev/eval person names disjoint
11. expected values absent from prompts
12. expected values absent from system prompt and tool schemas
13. no eval entity in system prompt or schemas
14. scenario fixtures consistent
15. no entity shared between eval tasks
16. no eval entity name in training or existing benchmarks
17. no exact or template match with training and legacy prompts (TF-IDF max: 0.142)

Per-run integrity checks (for all 4 completed ablation runs × 480 runs each):
- No ground-truth fields in any message
- Provenance/reliability fields only in their assigned configs
- Baseline never received memory
- Baseline tools never returned a memory-only answer
- Each store holds exactly its own task records

## Sealed test set

A 130-task test set exists but was **not used** in Campaign 2. It is reserved for final evaluation after methodology is frozen.
